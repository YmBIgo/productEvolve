# 開発フロー

### インデックスを作る
src/indexing.ts にて実行
→ 100個の製品にて、それぞれの製品動作とその各特徴を抽出

### 1周目を作る
「洗濯機」を例に示す

1. 洗濯機の基本的なやりたいことを抽出 →「衣服から汚れを落とす」
2. 「汚れを落とす」と同じ機能を、`all_features.json` から抽出
3. 2で抽出したものを、`inverted_features_index.json` から検索。洗濯機以外の製品を抽出
4. 一旦 3の各要素でアイデアを１つずつ出す
5. 4の各アイデアで、アイデアの不足部分を以下の分類で抽出する
   - NEED_IMPROVEMENT : そのアイデア自体に改善が必要
   - NEED_BEFORE_CARE : そのアイデアの前工程が必要
   - NEED_AFTER_CARE : そのアイデアの後工程が必要
   - COMPLETE : そのアイデアだけで十分要件を満たしている
   - FAILED : そのアイデアは不可能である
6. 5のアイデアの不足部分に応じて、アイデアを改善する
   - まず、5の結果がCOMPLETEかどうかを確認。COMPLETEなら7に移動
   - 次に、5の結果がFAILEDかどうかを確認。FAILEDならその探索経路を中止
   - 次に、探索深さが5以上なら7に移動
   - 次に、不足部分の不足キーワードを生成
   - 次に、不足キーワードと類似するアイデアを、`all_features.json` から抽出
   - 次に、類似するアイデアを`inverted_features_index.json`から検索。洗濯機以外の製品を抽出
   - 次に、そのアイデアの上位5件でアイデアを作る
   - 5に戻る
7. 結果を返す
